# Huawei Watch GT 4 Capability Matrix

Last reviewed: 2026-07-15.

This document records only capabilities supported by the official Huawei documentation listed below. It deliberately separates an explicit Huawei statement from a product inference and from a check that must be performed on a physical Watch GT 4 at runtime.

Status terminology:

- **Yes (direct)**: Huawei explicitly documents the capability for the relevant product family or API.
- **Conditional**: Huawei documents the API, but the application must check the Watch GT 4 device type, API level, hardware support, permission grant, or actual runtime behavior.
- **Not confirmed**: the reviewed official documentation does not establish support for Watch GT 4. Production code must not advertise or emulate it.
- **No**: the reviewed official API surface does not provide the requested value.

Huawei's current Wear Engine device list includes the WATCH GT series from GT 3 onward, so Watch GT 4 is a supported Wear Engine device. However, the archived Lite Wearable overview explicitly names Watch GT 2 Pro and Watch GT 3 and does not name Watch GT 4. Therefore, classifying every Watch GT 4 running HarmonyOS 5.0.0 as a Lite Wearable is an inference, not a verified official fact. The exact device type, API level, P2P support, sensors, and permissions must be verified on the target watch.

Local toolchain evidence is separate from device capability evidence. DevEco Studio `6.1.1.280` generated a HarmonyOS `6.1.1.125` project targeting API 24, and the round Lite Wearable Previewer runs the GymCoach harness. Huawei's Lite Wearable SDK page still documents compile SDK 6 or 10. API 24 is therefore recorded as the verified wizard target, not as the runtime API level of Watch GT 4; the discrepancy remains a real-device compatibility gate.

## Required runtime verification on a physical Watch GT 4

Before marking the companion as production-ready, record the following from the actual watch and Huawei phone pair:

1. Device type returned by Wear Engine and whether P2P is enabled.
2. Device API level and the feature gates selected from it.
3. Successful signed-HAP installation and application launch.
4. Heart-rate permission flow, valid sample cadence, screen-off behavior, and off-wrist behavior.
5. Runtime support for accelerometer, gyroscope, activity motion, wear detection, ambient temperature, vibration, and crown input.
6. Maximum stable message and file throughput under the documented limits.
7. Suspension, reopening, crash recovery, offline event retention, and synchronization after reconnect.

Until those checks pass, sensor and deep-background support must be reported as conditional rather than as a guaranteed Watch GT 4 capability.
